# 仿真启动相关命令

本文档记录 `feature/rl-simulator` 分支下 ROS-free Webots 仿真、自瞄端和实时状态观察器的常用启动命令。

## 1. 基础准备

在小电脑上进入项目目录，并确认在仿真分支：

```bash
cd ~/hfut_auto_aim-main
git switch feature/rl-simulator
chmod +x scripts/*.sh sim/webots/*.sh tools/sim/live_status.py
```

构建 detector-free 的 armor-pose 仿真自瞄入口：

```bash
./scripts/build_armor_pose_sim.sh
```

这个构建不需要 ONNX Runtime，适合当前 Webots armor-pose 直输仿真。如果要跑完整图像检测链路，才需要安装或指定 ONNX Runtime。

## 2. 三终端启动流程

### 终端 1：启动 Webots 仿真端

静止目标：

```bash
cd ~/hfut_auto_aim-main
./scripts/run_webots_armor_pose_sim.sh stationary \
  --batch --mode=fast --no-rendering --stdout --stderr
```

原地旋转目标：

```bash
cd ~/hfut_auto_aim-main
WEBOTS_TARGET_SPIN_RATE=1.0 ./scripts/run_webots_armor_pose_sim.sh stationary \
  --batch --mode=fast --no-rendering --stdout --stderr
```

左右移动目标：

```bash
cd ~/hfut_auto_aim-main
./scripts/run_webots_armor_pose_sim.sh moving \
  --batch --mode=fast --no-rendering --stdout --stderr
```

左右移动 + 原地旋转目标：

```bash
cd ~/hfut_auto_aim-main
WEBOTS_TARGET_SPIN_RATE=1.0 ./scripts/run_webots_armor_pose_sim.sh moving \
  --batch --mode=fast --no-rendering --stdout --stderr
```

说明：

- `--batch`：批处理模式运行 Webots。
- `--mode=fast`：尽量快速推进仿真时间。
- `--no-rendering`：不渲染画面，适合无显示器/SSH 环境。
- `--stdout --stderr`：把 Webots controller 日志打印到终端。

如果小电脑接了显示器，想看 Webots GUI、装甲板旋转和弹丸可视化，不要加
`--batch --mode=fast --no-rendering`：

```bash
cd ~/hfut_auto_aim-main
HFUT_WEBOTS_USE_XVFB=0 WEBOTS_TARGET_SPIN_RATE=1.0 \
./scripts/run_webots_armor_pose_sim.sh stationary
```

黄色小球表示当前计分系统里的飞行弹丸；绿色闪点表示命中，红色闪点表示未命中。
这些可视化只显示计分弹道，不改变命中率计算。

### 终端 2：启动自瞄端

```bash
cd ~/hfut_auto_aim-main
./scripts/run_armor_pose_sim.sh --strategy=predicted --diagnostics --rl-action
```

说明：

- `--strategy=predicted`：使用预测控制策略。
- `--diagnostics`：写出 `tracking_diagnostics.jsonl`，供状态观察和离线分析使用。
- `--rl-action`：开启 RL residual 钩子；没有 `rl_action.json` 时默认不施加残差。

### 终端 3：启动实时状态观察器

```bash
cd ~/hfut_auto_aim-main
./scripts/watch_sim_status.sh
```

典型输出：

```text
[SIM] t=12.48s seq=780 fps=62.5 wall=62.4 truth_lag=0.0ms
[TRACK] state=TRACKING(1) mode=NORMAL target=4 tracked=1 armors=4 track_win=100%
[AIM] yaw=0.06deg pitch=-3.05deg dist=3.01m fire=1 fire_win=96%
[ERR] yaw=0.114deg pitch=0.031deg target_err=2.7cm
[TIME] proc=1.1ms flight=133.7ms pred=184.9ms
[RL] enabled=1 valid=0 dyaw=0.000deg dpitch=0.000deg gate=1
[SCORE] shots=42 hits=38 miss=4 hit=90.5% dps=126.7
```

重点看：

- `[TRACK]`：是否稳定跟踪，`track_win` 是否接近 100%。
- `[AIM]`：云台目标角、距离、是否建议开火。
- `[ERR]`：yaw/pitch 误差和控制目标误差。
- `[TIME]`：处理延迟、飞行时间、总预测时间。
- `[RL]`：RL residual 是否实际生效。
- `[SCORE]`：发射数、命中数、miss、命中率和 DPS。

## 3. 桥接目录和生成文件

默认桥接目录：

```bash
~/hfut_auto_aim_webots
```

正常启动后应有这些文件：

```text
~/hfut_auto_aim_webots/armor_pose_frame.bin
~/hfut_auto_aim_webots/gimbal_command.bin
~/hfut_auto_aim_webots/tracking_diagnostics.jsonl
~/hfut_auto_aim_webots/target_truth.jsonl
~/hfut_auto_aim_webots/score.txt
~/hfut_auto_aim_webots/score_events.jsonl
```

含义：

- `armor_pose_frame.bin`：Webots -> 自瞄，装甲板三维位姿输入。
- `gimbal_command.bin`：自瞄 -> Webots，云台命令和 `fire_advice`。
- `tracking_diagnostics.jsonl`：自瞄端诊断日志。
- `target_truth.jsonl`：Webots 真值日志。
- `score.txt`：实时计分统计。
- `score_events.jsonl`：每次 fired/hit/miss 事件。

不要默认使用 `/tmp/hfut_auto_aim_webots`。snap 版 Webots 可能有独立 `/tmp` 命名空间，会导致 Webots controller 写入的位置和普通终端读取的位置不是同一个。

## 4. 旋转速度参数

旋转目标通过 `WEBOTS_TARGET_SPIN_RATE` 控制，单位是 `rad/s`。

常用值：

```text
WEBOTS_TARGET_SPIN_RATE=1.0  -> 57.3 deg/s  -> 9.55 rpm
WEBOTS_TARGET_SPIN_RATE=2.0  -> 114.6 deg/s -> 19.1 rpm
WEBOTS_TARGET_SPIN_RATE=3.0  -> 171.9 deg/s -> 28.6 rpm
```

示例：

```bash
WEBOTS_TARGET_SPIN_RATE=2.0 ./scripts/run_webots_armor_pose_sim.sh stationary \
  --batch --mode=fast --no-rendering --stdout --stderr
```

如果不想每次命令行设置，可以修改：

```text
sim/webots/config/target_robot.env
```

例如：

```bash
: "${WEBOTS_TARGET_SPIN_RATE:=1.0}"
```

## 5. 左右移动参数

`moving` 场景会默认开启横向移动，主要参数在：

```text
sim/webots/run_moving_spin_target_test.sh
sim/webots/config/target_robot.env
```

常用参数：

```text
WEBOTS_TARGET_LATERAL_AXIS=y
WEBOTS_TARGET_LATERAL_AMPLITUDE=1.5
WEBOTS_TARGET_LATERAL_SPEED=1.0
WEBOTS_TARGET_LATERAL_ACCEL=3.0
WEBOTS_TARGET_LATERAL_DECEL=3.0
WEBOTS_TARGET_LATERAL_INITIAL_DIRECTION=1.0
```

示例：降低横移速度和幅度：

```bash
WEBOTS_TARGET_LATERAL_AMPLITUDE=1.0 \
WEBOTS_TARGET_LATERAL_SPEED=0.6 \
./scripts/run_webots_armor_pose_sim.sh moving \
  --batch --mode=fast --no-rendering --stdout --stderr
```

## 6. 计分参数

计分参数主要在：

```text
sim/webots/config/camera_robot.env
```

常用参数：

```text
WEBOTS_SCORE_ENABLED=true
WEBOTS_FIRE_RATE_HZ=20.0
WEBOTS_BULLET_SPEED=22.5
WEBOTS_SCORE_GRAVITY=9.80665
WEBOTS_SCORE_ARMOR_WIDTH=0.135
WEBOTS_SCORE_ARMOR_HEIGHT=0.135
WEBOTS_SCORE_MAX_FLIGHT_TIME=2.0
WEBOTS_PROJECTILE_VISUAL_ENABLED=true
WEBOTS_PROJECTILE_VISUAL_RADIUS=0.025
WEBOTS_PROJECTILE_MARKERS_ENABLED=true
WEBOTS_PROJECTILE_MARKER_RADIUS=0.045
WEBOTS_PROJECTILE_HIT_MARKER_TTL_MS=220.0
WEBOTS_PROJECTILE_MISS_MARKER_TTL_MS=220.0
```

示例：降低射频到 10 发/s：

```bash
WEBOTS_FIRE_RATE_HZ=10.0 ./scripts/run_webots_armor_pose_sim.sh moving \
  --batch --mode=fast --no-rendering --stdout --stderr
```

`hit_rate` 的计算口径：

```text
hit_rate = hits / (hits + misses)
```

仍在飞行中、尚未命中或超时的弹丸不计入命中率分母，所以可能出现：

```text
shots > hits + misses
```

这是正常现象。

## 7. 离线分析命令

实时测试结束后，可以生成诊断汇总：

```bash
python3 tools/diagnose_tracking.py \
  --bridge-dir ~/hfut_auto_aim_webots \
  --output ~/hfut_tracking_summary.json

cat ~/hfut_tracking_summary.json
```

也可以生成 RL baseline 汇总：

```bash
python3 tools/rl/replay_analyzer.py \
  --bridge-dir ~/hfut_auto_aim_webots \
  --config configs/rl_sim.yaml \
  --output ~/hfut_rl_baseline.json

cat ~/hfut_rl_baseline.json
```

## 8. 常见问题

### `watch_sim_status.sh` 一直 waiting

检查 Webots 端是否正在运行，桥接目录是否有文件：

```bash
ls -lh ~/hfut_auto_aim_webots
```

至少应看到：

```text
armor_pose_frame.bin
target_truth.jsonl
```

### 自瞄端一直 `no armor-pose frame for 2s`

说明自瞄端没有读到 Webots 写出的 `armor_pose_frame.bin`。先检查两端是否使用同一个桥接目录：

```bash
echo $WEBOTS_ROS_FREE_BRIDGE_DIR
ls -lh ~/hfut_auto_aim_webots
```

### Webots 退出时提示 controller crashed


如果是按 `Ctrl+C` 停止 Webots 后出现，通常是 Xvfb/Webots 被强制停止导致，可以先忽略。

### `SCORE` 长时间没有变化

检查自瞄端是否输出 `fire=1`：

```text
[AIM] ... fire=1
```

如果 `fire=0`，计分器不会登记发射。

### 真实上车效果能否直接看仿真命中率

不能直接等价。当前仿真是 armor-pose 直输，主要用于比较不同控制策略、预测参数、RL residual 的相对效果。真实上车还会受到图像检测、曝光、运动模糊、串口延迟、云台动态、弹速波动和机械误差影响。
